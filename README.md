# Fines & Fees

React + FastAPI workspace for customer deductions across Logistics, Warehouse and Manufacturing. Replaces the original browser-only mock services with database-backed authentication, account approvals, filters, review decisions and audit history.

## Run locally

Python 3.10+ and Node 22.12+ are required.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirement.txt
cd backend
cp .env.example .env
python bootstrap.py
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

`bootstrap.py` prompts for the first administrator's name, email and password. There are no built-in accounts. In a second terminal:

```bash
cd frontend
npm ci
npm run dev
```

Open http://localhost:5173. Sign in with the role used for the account. New registrations await administrator approval. Administrators access **User Management** from their profile menu in the lower-left sidebar. Viewer is the regular user role; Super User can review fines. Admin also approves registrations and imports datasets. Signing out revokes the server session. Sessions expire after eight hours.

The development proxy forwards `/api` to port 8000. For separate deployment, set `VITE_API_URL` before building, and set `FRONTEND_ORIGIN` on the API to the exact allowed frontend origin (comma-separated for multiple origins). Serve both over HTTPS.

## Workflow

1. Administrator selects **Import dataset**, uploads `.xlsx`, and validates it.
2. All rows must pass structural validation before explicit import. Import is transactional; invalid files write no records. Reuploading the identical file is rejected.
3. Executive Summary shows total cases, gross deductions, pending exposure, charts and source-area totals. Filters call the middleware; source cards and pending queue open the corresponding detail view.
4. Super User/Admin opens a fine, selects Valid, Invalid or Pending and supplies a comment. The middleware saves the reviewer, time, old/new status and comment. Version checks prevent stale decisions overwriting another review.
5. Viewer can read and export, but cannot update decisions. API permissions enforce this independently of the UI.

The initial database is empty. There is no synthetic data fallback and no automatic valid/invalid classifier. Business classification needs agreed rules and supporting evidence; reducing the 10–15 day process has not yet been measured.

## Excel contract

Only `.xlsx`, at most 5 MB and 10,000 data rows. The active sheet must contain these exact column names:

| Column | Value |
| --- | --- |
| CustomerID | Nonempty customer identifier; use text cells to preserve leading zeroes |
| Fines Imposed | Nonnegative INR amount, up to two decimal places |
| Status | `Valid`, `Invalid`, `Pending` |
| Reason | Nonempty reason |
| Date | Excel date cell or `YYYY-MM-DD` |
| SourceArea | `Logistics`, `Warehouse`, `Manufacturing` |

Extra columns are ignored. Validation checks structure, types and allowed values; it does not certify business validity. No actual dataset was supplied, so final mapping must be checked against the validated workbook. The direct fine-creation API also accepts `customerName` and `orderReference`.

## Middleware endpoints

Interactive documentation: http://localhost:8000/docs. Authenticated endpoints require `Authorization: Bearer <token>`.

| Screen/action | API |
| --- | --- |
| Registration | `POST /api/auth/signup` |
| Login/session/logout | `POST /api/auth/signin`, `GET /api/auth/me`, `POST /api/auth/logout` |
| Account approvals | `GET /api/users/requests`, `POST /api/users/{id}/decision` |
| Filtered fines | `GET /api/fines` |
| Excel export | `POST /api/exports/fines` |
| Global KPI integration | `GET /api/dashboard` |
| Admin record creation | `POST /api/fines` |
| Review timeline / decision | `GET/POST /api/fines/{id}/reviews` |
| Dataset validation | `POST /api/imports/validate` (multipart `file`) |
| Dataset import | Same endpoint with `?commit=true` |

Fine filters: `status`, `customerId`, `sourceArea`, `fromDate`, `toDate`, `reason`, `search`. UI KPI charts use the same filtered API rows as the detail table. `/api/dashboard` provides an unfiltered aggregate for other integrations. Excel export is generated by FastAPI from the currently filtered record IDs. Monetary reporting uses INR throughout.

## SQL Server / SSMS

SSMS is the administration client; the API connects to SQL Server itself using SQLAlchemy and pyodbc.

1. Create the target database in SQL Server and a suitable application login.
2. Install Microsoft ODBC Driver 18 and `pip install -r backend/requirements-sqlserver.txt`.
3. Remove `DATABASE_URL` from `.env`; configure all `DB_*` values using `.env.example`. Encryption is on; certificate verification defaults to on.
4. Run bootstrap/start the API against the empty database to create the initial tables.
5. Import the validated workbook into that target database through the same API.

SQLite is only the local default. Switching configuration does not migrate existing SQLite rows. SQL Server connectivity and concurrency have not been tested against a live SQL Server instance. Use reviewed schema migrations for subsequent production schema changes; `create_all` only creates missing tables.

## Verification

```bash
pip install -r backend/requirements-dev.txt
pytest backend/tests -q
cd frontend
npm run build
```

API tests cover registration approval, authentication/logout, permission boundaries, mandatory comments, optimistic concurrency, filtering, source totals, transactional validation and duplicate-file protection.

Before internet-facing production use, configure operational protections such as login throttling, deployment monitoring/backups and schema migrations. Password reset/email delivery is not implemented. The inherited tracked `.env` and bytecode were removed from the current source; historical commits in the original repository still contain them. Rotate any real credentials previously stored there.
